# Two-week home-gym program

LiftLog 4.4 implements the standard program supplied by the user in the development conversation. Presets are instructions, not historical records. The six sessions in each week are Upper Push, Lower Push, Joint + Balance, Upper Pull, Lower Pull, Core + Carries. Both weeks retain their own exercises, working-set counts, ranges, alternatives, cardio instructions and coaching notes. Day 7 is off. Main lifts and low-fatigue sessions retain their effort/rest guidance; no unsupported primary/secondary/tertiary hierarchy was added.

`program.js` defines stable `H1D1` through `H2D6` keys and separate movement IDs for materially different exercises. Existing suitable movement IDs are reused where the exercise is the same, preserving historical references and custom increments. Library hydration adds missing exercises without overwriting existing definitions, history, custom routines or an unfinished session. It does not write storage merely because an update loaded.

The home-gym suggestion follows the latest completed program session by workout date/start time. It advances after a partially completed session, while the omitted work stays skipped in that record. It never invents missed workouts or schedules make-up sets. Sessions with no completed entries do not advance or consume the manual selection. Calendar Mondays have no effect. Day 6 leads to visible off-day guidance and the next week's first training session when the user is ready. Users can select either week's day directly, and earlier A/B/C routines remain available below the program. Travel routines continue independently.

Each planned item stores a copy of its prescription, preserving the meaning of recorded targets if future defaults change. Sets retain editable actual values and an explicit warm-up/working role. Completion still takes one tap and saves locally immediately. Skipped sets remain excluded from completion, cardio totals and progress. Finish confirmation explicitly marks pending sets skipped. Warm-up and work slots recall the most recent actual value at the same ordinal and machine; an omitted middle set never shifts later weights. Imported backups from earlier versions remain valid. Legacy unlabelled extra sets remain editable references; the app does not guess which were warm-ups. Known program entries follow the current prescription's working count rather than copying another day's count.

The standard side-plank alternative for Week 2 Core + Carries is available through that exercise's options. It installs its prescribed seconds and count. General substitutions remain available; a general swap drops the original prescription and machine metadata so they cannot mislabel the replacement.

Farmer carry and Pallof hold store both seconds and load. Farmer-carry load is per hand. Unit conversion changes their recorded weights while retaining durations. Machine names are optional for historical compatibility, but the UI requests them, separates progress by identity, and clears unmatched pending loads when switching identity. Completed sets keep their original machine: another machine needs a separate entry. Unspecified legacy machines remain a separate progress group.

All fields are additive under schema 1 and the unchanged `liftlog.personal.v1` storage key. Complete backups include prescriptions, roles, skips and machines, including active workouts and saved routines. Restore validates these before mutation. CSV includes machine, set type, status and prescribed ranges; shared summaries distinguish actual and skipped work. The static program creates no workout records and needs no account, API, network service or Google synchronization.

Validation includes independent fixtures for all 76 exercise entries, all 12 session starts, both week boundaries, arbitrary mid-cycle selection, old-record edits, zero-completion sessions, partial finishes, warm-ups, missing middle sets, changed counts across sessions, loaded carries, the side-plank alternative, machine changes and backup round trips. Browser checks cover the new selector plus the existing offline, recovery, single-writer, cardio and original-v4 upgrade workflows. Automated Chromium/WebKit checks do not substitute for testing on a physical iPhone.
